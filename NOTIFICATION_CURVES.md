# Настраиваемая почасовая кривая уведомлений

## Что сравнивается

Для каждого часа отдельно рассчитывается ожидаемая энергия по прошлым сопоставимым дням.
N — число последних дней с данными, а не процент тревоги. Поиск ограничен N × 7 + 7 календарными днями.
Выборка исключает анализируемый день и будущее. При диапазоне обе даты включительны,
но используются только даты до проверяемого дня. Даты и почасовые значения показаны под графиком.

Методы: среднее, медиана, линейный тренд по фактическим датам для каждого часа.
Тренду нужны минимум два значения; для остальных действует выбранный минимум.
Рабочие дни определяются как пн–пт, выходные — сб–вс. Отдельного календаря праздников пока нет.
Можно выбрать тот же день недели или все дни.

Тревога: абсолютная разница больше нуля и не меньше
max(|ожидаемое| × процент / 100, минимальное абсолютное отклонение).
Проверка двусторонняя. При нулевой базе процент для ненулевого факта не определён,
но сравнение по абсолютной разнице продолжает работать. Пропуски и неполная энергия — NULL.
Для сравнения одного часа нужны одинаковые множества счётчиков; полностью отсутствующие во всём
доступном наборе дат счётчики без внешнего ожидаемого списка обнаружить нельзя.

## Два режима

- daily: 24 часа завершённых суток, чтение существующих часовых агрегатов.
- live: текущие сутки, только завершённые часы по Москве. Адаптер читает исходник по подтверждённому
  профилю, проверяет полноту и дубликаты, агрегаты не перезаписывает. Кеш данных — до 5 минут.
  График в неизменённом оперативном режиме обновляется раз в минуту.

В локальном Compose разрешено чтение активного проверенного профиля из adapter_control,
если свой активный профиль adapter_workstation ещё не выбран. Старый профиль должен использовать
известный локальному адаптеру alias. Это только чтение, не активация и не изменение серверного профиля.

## Сохранение и письма

Предварительный просмотр — POST /api/notifications/preview/, без изменения настроек и отправки писем.
GET того же адреса — границы доступных завершённых дат. PATCH settings/ сохраняет baseline вместе
с enabled и threshold_percent. Новые настройки включаются только явным сохранением.

Миграция notifications.0002_curve_rules добавляет поля JSONB и версионирование отчётов.
Старые записи сохраняются. Новое правило отделено от legacy enabled: старый worker .42 не применяет
к нему прежний постоянный средний уровень. При чтении API возвращается effective enabled.
DB-default полей сохраняют возможность вставки записей старой версией.
Для новых правил worker использует отдельный advisory lock 482019774; legacy сохраняет 482019773.

Отчёт уникален по пользователю, дню и хешу конфигурации. Старые версии сохраняются.
Оперативный отчёт обновляется, но письмо отправляется не чаще одного раза на день/версию.
delivery_snapshot сохраняет содержимое, по которому началась отправка.
Повтор после неоднозначной SMTP-отправки исключён. SMTP не включается и не настраивается автоматически.

## Запуск

Обычный локальный стек использует существующие базы через SSH на .42.
После сборки нового backend явно примените только миграцию уведомлений:

```powershell
docker compose -p smart-energy-workstation -f docker-compose.local.yml build backend adapter frontend
docker compose -p smart-energy-workstation -f docker-compose.local.yml up -d ssh
docker compose -p smart-energy-workstation -f docker-compose.local.yml run --rm --no-deps backend python manage.py migrate notifications
docker compose -p smart-energy-workstation -f docker-compose.local.yml up -d --no-build
Start-Process https://localhost:8443/notifications
```

Не запускайте миграции и интеграционные тесты на исходной базе показаний.

## Проверки

Frontend из Фронт/smart_energy:

```powershell
npm ci
npx playwright install chromium
npm run test:notifications:coverage
npm run test:ux
npm run test:mapping
npm run test:dashboard
npm run lint
npm run build
```

Backend на отдельной tmpfs PostgreSQL, без рабочих настроек:

```powershell
docker compose -p smart-energy-notification-checks -f docker-compose.notification-tests.yml run --build --rm tests
docker compose -p smart-energy-notification-checks -f docker-compose.notification-tests.yml down
```

Unit-тесты проверяют формулы, N, выбор диапазона, типы дней, отсутствие утечки целевого дня,
пустые/неполные данные, нулевую базу, пороги, версии правил, авторизацию, SMTP и очередь.
SQL-интеграция выполняется на тестовой PostgreSQL. Браузерные сценарии изолируют API,
проверяют настоящий React/график в Chromium, десктоп/телефон, светлую/тёмную темы,
ошибки, сохранение, клавиатуру и отсутствие случайной записи при предварительном просмотре.
Они не проверяют доставку в реальный почтовый ящик и не подменяют живой вход пользователя.

Покрытие не является обещанием отсутствия ошибок. Отчёты покрытия и браузерные снимки
создаются в игнорируемых coverage/ и test-results/.
