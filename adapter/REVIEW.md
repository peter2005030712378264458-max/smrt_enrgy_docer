# Ревью адаптера и неполных источников

Проверена ветка `feature/adapter-missing-columns-review`, основанная на `feature/vm42-deployment` (`6f061bb`). Дата проверки: 31.10.2026. Проверки выполнялись локально, на изолированном PostgreSQL 13. Рабочие базы и развёртывание на ВМ в рамках этого ревью не изменялись.

## Что проверено

- Обследование PostgreSQL, список таблиц, реальные имена/типы/комментарии столбцов, предложения соответствий и права чтения.
- Валидация профиля, единицы, часовые пояса, преобразование исходных ID и проверка справочника.
- Почасовая статистика, суточные средние, энергия, качество исходных данных и поведение при пропусках.
- Замена обеих таблиц, блокировки, откат, повторный запуск, прогресс, очередь, preview/apply и расписание.
- Страница «Источники и агрегации»: карточки, сохранённые сопоставления, доступность показателей, предупреждения и история заданий.
- Минимальные связанные исправления NULL в SQL Django/аналитики и отображении дашборда.

## Найденные и исправленные проблемы

| Важность | Проблема до исправления | Результат |
|---|---|---|
| Высокая | Профиль требовал общую активную мощность либо три фазы; удаление любого ранее назначенного измерения обрывало SQL | Обязательны только время/ID. Отсутствующий или недоступный необязательный столбец становится NULL с предупреждением; остальные измерения агрегируются |
| Высокая | Неполный набор фаз мог давать ложную общую мощность и энергию | Для суммы нужны все три корректные фазы одного показания. Частичные фазы остаются самостоятельными показателями |
| Высокая | Строки без даты могли выпасть из фильтра периода, а без ID — из группировки | NULL времени и пустой/NULL ID явно останавливают расчёт до замены агрегатов. Отсутствующие обязательные столбцы и неверный тип времени дают отдельную понятную ошибку |
| Высокая | Неполная мощность внутри часа могла давать частичную энергию как полную; SQL/JavaScript подменяли неизвестные значения нулём или исключали неизвестного участника из суммы | Сохранённая энергия остаётся неизвестной в часе, сутках и итогах. Настоящий ноль сохраняется. График имеет пропуски; карточки показывают отсутствие значения. NULL-часы не считаются наблюдениями Z-теста |
| Высокая | Структура могла измениться после preview без обязательной повторной проверки; новый неуспешный preview оставлял старую отметку проверки | Preview сохраняет отпечаток назначенных столбцов/типов; ручная запись проверяет его. Новый preview атомарно сбрасывает отметку проверки до успеха. Интерфейс использует последнюю проверку выбранного периода |
| Средняя | Тайм-аут примеров строк скрывал успешно полученную структуру; предложения не учитывали совместимость типов и SELECT | Каталог возвращается независимо от доступности примера; предупреждение объясняет отсутствие строк. Предложения учитывают типы/чтение, доступность столбца не определяется по пяти значениям |
| Средняя | Нестандартные имена из каталога могли не пройти разбор; одинаковые таблицы с разным написанием могли получить разные advisory lock | Поддержаны квалифицированные экранированные имена таблиц/представлений. Блокировки используют разобранную пару схема/таблица |
| Средняя | NaN одной фазы портил среднее остальных; float Infinity мог упасть при преобразовании к numeric на PostgreSQL 13 | Неконечные измерения превращаются в NULL до преобразования/вычисления. Остальные корректные фазы сохраняются |

Имена и комментарии карточек берутся из каталога PostgreSQL (`pg_attribute`, `pg_type`, `col_description`). Встроенные подписи показателей и список синонимов принадлежат приложению. Синоним предлагает соответствие, но не доказывает смысл величины или единицу; автоматической активации нет. Ручное соответствие не перезаписывается при применении предложений.

## Поведение при неполных данных

| Ситуация | Агрегация и интерфейс |
|---|---|
| Нет столбца времени/ID либо нет SELECT на него | Ошибка; существующие агрегаты сохраняются |
| Время задано текстом/числом | Ошибка; дата не угадывается и не заменяется текущей |
| Есть NULL времени | Остановка независимо от периода: строку невозможно отнести к суткам |
| NULL или пустой ID в выбранном периоде | Остановка; счётчик не выдумывается и строка не отбрасывается молча |
| Нет любого из 20 необязательных столбцов | Сохраняются доступные показатели, недоступные — NULL, появляется предупреждение |
| Только время и ID | Считаются строки и проверяется качество/справочник; измерения и энергия — NULL |
| Только напряжение, частота, ток или отдельная фаза | Сохраняются доступные показатели; общей активной мощности и энергии нет |
| Нет общего значения мощности, но есть три корректные фазы | Используется сумма трёх фаз соответствующего вида мощности |
| NULL/NaN/Infinity измерения | Не считается нулём; допустимые независимые измерения сохраняются |
| Измеренная мощность равна 0 | Корректное нулевое измерение; энергия равна 0 |
| Мощность предусмотрена структурой, но невалидна у всех счётчиков | Существующая проверка качества блокирует запись, защищая прежние агрегаты |
| Полной мощности нет в самой структуре | Полнота суток оценивается по числу исходных строк, сохраняются остальные показатели |
| У одного счётчика нет мощности, у других есть | Предупреждение; энергия этого счётчика и полный итог неизвестны, доступные значения остальных сохраняются |

После удаления столбца между preview и ручной записью сначала требуется новый preview. Если задание ждало в очереди до следующих суток, исполнитель повторно проверяет границу завершённых дней, чтобы не записать день вне preview. После обновления приложения старые проверки без отпечатка также нужно повторить. Формат профиля, таблицы назначения и схема управления не требуют миграции.

## Сохранённые гарантии

Источник читается в read-only сессии. Динамические имена экранируются через `psycopg.sql.Identifier`, значения параметризуются, браузер выбирает серверный псевдоним подключения. Проверены внутренний токен и права staff в Django.

Замена почасовых и суточных строк остаётся одной транзакцией на сутки. Сохраняются блокировки назначения, откат дня, идемпотентность, контроль пустого источника, дубликатов, интервала, справочника и исчезновения счётчиков. Уже завершённые сутки могут быть сохранены при ошибке следующих суток — атомарность всего многодневного задания не обещается.

Часовой пояс исходного `timestamp` задаётся явно, выходные сутки остаются московскими. Незавершённые сутки исключаются. Расписание включается отдельно. Формулы режимов энергии и значение `ENERGY_USE_STORED_ENERGY` не переключались.

## Проверки

```powershell
# Из корня проекта
docker compose -p smart-energy-adapter-tests -f adapter/tests/compose.yml run --build --rm tests

# После завершения основного набора, отдельно от него
docker compose -p smart-energy-adapter-tests -f adapter/tests/compose.yml --profile ui up -d ui
# Дождаться запуска Django, затем:
docker compose -p smart-energy-adapter-tests -f adapter/tests/compose.yml exec -T ui python -m adapter.tests.http_smoke

# Из Фронт/smart_energy
npm run test:mapping
npm run test:dashboard
npm run lint
$env:VITE_API_URL = '/api'
npm run build
tar -czf frontend-dist.tar.gz -C dist .
```

Результат: 48 тестов адаптера, 33 Django, 14 аналитики; дополнительные проверки реальных SQL потребителей; 10 проверок сопоставлений и 5 проверок NULL дашборда. HTTP smoke проверяет JWT, права, внутренний токен, обследование, preview, apply, активацию и результат в БД. Удаление каждого необязательного столбца и 11 минимальных наборов проверены отдельными подслучаями на PostgreSQL; также проверены комментарии, представления, domain-типы, SELECT отдельных столбцов, тайм-аут примера, часовые пояса и сохранность прежних агрегатов.

Визуальная проверка в браузере не завершена: Computer Use остановился, поскольку не смог надёжно определить текущий URL Chrome в Windows. Проверки логики, ESLint, сборка и HTTP/SQL не заменяют ручную проверку перетаскивания и внешнего вида. Изменения UI включены в Docker-архив фронтенда.

## Оставшиеся ограничения

- Пять примеров не подтверждают единицы, интервал или качество суток. Оператор по-прежнему подтверждает профиль и выполняет preview.
- Поиск NULL времени выполняется по всему источнику. Без подходящего индекса/подготовленного представления он может быть дорогим и закончиться настроенным тайм-аутом; запись при ошибке не продолжается. Адаптер не создаёт индексы в рабочем источнике.
- Не восстанавливаются отсутствующие строки и неизвестное потребление между ними. Даже допустимое покрытие не гарантирует физическую полноту энергии; алгоритм оценки по подтверждённому интервалу сохранён.
- При `ENERGY_USE_STORED_ENERGY=0` энергия по-прежнему оценивается из доступной средней мощности, даже если сохранённая энергия часа неизвестна из-за неполных измерений. Переход на сохранённую энергию требует отдельно согласованного пересчёта истории и включения флага; это ревью его не включает.
- Существующие агрегаты не хранят отдельный счётчик корректных значений каждой метрики для последующего взвешивания в API. Суточные средние самого адаптера используют отдельные суммы/счётчики; дальнейшее объединение средних в дашборде сохраняет прежнее взвешивание по `points_count`. Изменение схемы агрегатов выходит за рамки этого ревью.
- Неизвестный полностью отсутствующий счётчик нельзя обнаружить без ожидаемого перечня; проверяется сравнение с имеющимися агрегатами. Объединение независимых источников в одни таблицы за те же сутки не поддерживается.
- Старые ошибочно рассчитанные агрегаты автоматически не исправляются. Исправления начинают действовать при новом расчёте выбранного периода.
