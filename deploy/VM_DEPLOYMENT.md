# Запуск на ВМ 193.232.208.42

Используется установленный Docker и `docker-compose 1.29.2`. Запускайте команды
из корня проекта на Linux-ВМ. Конфигурация ВМ находится в стандартном
`docker-compose.yml`. Локальная версия сохранена в ветке `feature/ssh-less-connection`.

## Первый запуск

В отдельном терминале на ВМ откройте SSH-туннель к PostgreSQL и оставьте его работающим:

```bash
ssh -N -L 127.0.0.1:15432:localhost:5432 restricted_user@193.232.208.50
```

В основном терминале:

```bash
cd /home/restricted_user/smrt_enrgy_docer
docker-compose config --quiet
docker-compose up -d --build
docker-compose ps
```

Откройте `https://193.232.208.42`. Без действующей сессии появится страница входа,
с сессией — дашборд. Nginx в контейнере frontend принимает HTTPS на 443,
отдаёт React и направляет `/api/` в Django. Django и FastAPI слушают только
`127.0.0.1:5000` и `127.0.0.1:8001`. Контейнеры используют сеть хоста для доступа
к SSH-туннелю на `127.0.0.1:15432`. Для доступа извне разрешите входящий порт 443.

## Существующие настройки и сертификат

По умолчанию Compose читает заполненные `.env.example` обоих Python-сервисов.
Параметры БД и токен аналитики повторно вводить не нужно. Если используете отдельные
существующие `.env`, перед запуском укажите их пути:

```bash
export BACKEND_ENV_FILE='./Бэк/project_backend/.env'
export ANALYTICS_ENV_FILE='./Аналитический сервис/Analytical_service/.env'
```

Сертификат и ключ должны существовать как файлы `ssl/nginx.crt` и `ssl/nginx.key`.
Если они находятся в другом месте, укажите реальные пути:

```bash
export TLS_CERTIFICATE_PATH=/путь/к/сертификату.crt
export TLS_KEY_PATH=/путь/к/ключу.key
```

Корневой `.env`, если он существует, используется Compose для этих переменных.
Файлы `.env.vm` и дополнительные скрипты для запуска не требуются.

Порты 443, 5000 и 8001 должны быть свободны. Если на ВМ уже работают контейнеры
этого проекта, перед запуском новой версии выполните `docker-compose down`.
Apache на порту 80 может продолжать работать. Самоподписанный сертификат должен
включать IP ВМ в SAN; для доступа без предупреждения браузера доверьте его на клиенте.

## Проверка, остановка и обновление

```bash
docker-compose logs --tail=100
curl -k -I https://193.232.208.42/
curl -k -i https://193.232.208.42/api/auth/me/
```

Запрос `/api/auth/me/` без JWT возвращает `401`. Django при старте ожидает БД,
применяет миграции и запускает Gunicorn. Если ключ Django не указан, он создаётся
в постоянном томе `smart-energy-vm_django-secret` и сохраняется между запусками.

Для остановки используйте `docker-compose down`. При обновлении сначала остановите
контейнеры, затем пересоберите и запустите их:

```bash
docker-compose down
docker-compose up -d --build
```

Не добавляйте `-v` при обычной остановке: это удалит том с ключом сессий.
