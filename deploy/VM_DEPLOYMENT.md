# Запуск на ВМ 193.232.208.42

Эта конфигурация предназначена для Linux-ВМ с Docker Compose, Nginx и
SSH-доступом к PostgreSQL. Используется ветка `feature/vm-deployment`.

```text
Браузер → Nginx в frontend HTTPS :443
             ├── /, /login, /dashboard → React
             └── /api/ → Django 127.0.0.1:5000 → FastAPI 127.0.0.1:8001
Django / FastAPI → SSH 127.0.0.1:15432 → PostgreSQL на 193.232.208.50:5432
```

Контейнеры используют сеть хоста Linux, чтобы видеть SSH-туннель на loopback.
Nginx в контейнере frontend принимает HTTPS на внешнем порту 443 и использует
существующий сертификат ВМ. Apache не участвует в обработке запросов приложения.
Для URL `https://193.232.208.42` без номера порта используется 443.

## 1. Настройки приложения

Скрипт запуска использует заполненные файлы сервисов: `.env.example`, затем `.env`
и `.env.local`, если они существуют. Повторно вводить параметры БД и токен аналитики
не нужно. Корневые `.env` и `.env.vm`, если существуют, дополняют эти настройки.

Из корня репозитория на ВМ:

```bash
git switch feature/vm-deployment
```

Существующий `DJANGO_SECRET_KEY` используется автоматически. Если он не задан,
при первом запуске создаётся ключ подписи JWT в Docker-томе `smart-energy-vm_django-secret`.
Ключ сохраняется при пересоздании контейнера. Не удаляйте этот том через `down -v`
при обычном обновлении: смена ключа завершит существующие сессии.

Сертификат и приватный ключ по умолчанию берутся из `./ssl/nginx.crt` и
`./ssl/nginx.key` относительно корня репозитория. Если они находятся в другом месте,
укажите только `TLS_CERTIFICATE_PATH` и `TLS_KEY_PATH` в существующем корневом `.env`
или необязательном `.env.vm`. Пример дополнительных настроек — `deploy/vm.env.example`.
Можно указать абсолютные пути. Оба файла монтируются во frontend только для чтения;
отсутствующие файлы не создаются.

## 2. SSH-туннель

Для запуска с вводом пароля откройте отдельный терминал на ВМ:

```bash
ssh -N -L 127.0.0.1:15432:localhost:5432 restricted_user@193.232.208.50
```

Оставьте терминал открытым. При закрытии туннеля запросы к БД перестанут работать.

Для автоматического запуска используйте `smart-energy-db-tunnel.service`.
Понадобится SSH-ключ, который уже разрешён для `restricted_user` на сервере БД.
Разместите ключ в `/etc/smart-energy/ssh_key` с правами `600`; сохраните проверенный
ключ сервера в `/etc/smart-energy/known_hosts`. Закройте ручной туннель перед
запуском службы, чтобы освободить порт 15432.

```bash
sudo cp deploy/smart-energy-db-tunnel.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now smart-energy-db-tunnel
sudo systemctl status smart-energy-db-tunnel
```

## 3. Контейнеры

Перед запуском убедитесь, что порт 443 свободен для frontend:

```bash
sudo ss -ltnp '( sport = :443 )'
```

Контейнеры из `docker-compose.app.yml` нельзя одновременно запускать на той же
ВМ на портах 443/5000/8001: сначала остановите их, если они там есть.

```bash
sh deploy/run-vm.sh config --quiet
sh deploy/run-vm.sh build
sh deploy/run-vm.sh run --rm --no-deps frontend nginx -t
sh deploy/run-vm.sh up -d --build
sh deploy/run-vm.sh logs --tail=100
```

Django ждёт доступности БД, применяет миграции и запускается через Gunicorn.

## 4. HTTPS на Nginx

Конфигурация `Фронт/smart_energy/nginx.vm.conf` включается в образ frontend.
Nginx слушает 443 на интерфейсах ВМ, отдаёт React и направляет `/api/` в Django.
Порты Django и FastAPI привязаны к `127.0.0.1`; внешний доступ к ним не нужен.

На адресе приложения порт 443 должен занимать контейнер frontend. Если другой
сервис уже занимает этот порт, устраните конфликт его привязки перед запуском.
Apache может продолжать обслуживать HTTP на 80. Разрешите входящие соединения
на 443 в сетевых настройках ВМ.

## 5. Проверка

```bash
curl -k -I https://193.232.208.42/
curl http://127.0.0.1:8001/health
curl -k -i https://193.232.208.42/api/auth/me/
```

Последний запрос без JWT должен возвращать `401`, а не `502`.
При открытии корня сайта сначала проверяется refresh-cookie: без действующей
сессии открывается `/login`, с сессией — `/dashboard`. Проверьте вход,
перезагрузку страницы и выход. Cookie действует до суток и передаётся по HTTPS.
Параметр `?preview=1` не включает обход входа в production-сборке.

Самоподписанный сертификат должен быть доверенным на клиенте и включать IP
`193.232.208.42` в Subject Alternative Name, иначе браузер покажет предупреждение.
