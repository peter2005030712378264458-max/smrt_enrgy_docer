# Локальные контейнеры с базами через SSH на .42

Приложение работает на этом компьютере. Базы и исходные показания остаются существующими:
локальный SSH-контейнер → .42:25433 (student) и .42:25432 (туннель к .50/paradigm_db).
Локальный PostgreSQL не создаётся. Адрес сайта: https://localhost:8443/.

## Первый запуск

Docker Desktop должен быть запущен. Файлы deploy/vm42/secrets/target_ssh_password и known_hosts
должны содержать ваши существующие SSH-настройки. Параметры PostgreSQL вводятся отдельно:

```powershell
cd C:\Users\Илья\.vscode\CODE\Project_Smart_energy_local-features
python deploy/local/configure.py
powershell -ExecutionPolicy Bypass -File deploy/local/start.ps1
```

При явном разрешении владельца можно вместо ручного ввода выполнить
`python deploy/local/configure.py --from-vm`: это прочитает только необходимые параметры подключения
из backend на .42 и запишет в игнорируемый deploy/local/app.env без вывода паролей.

configure.py сохраняет существующие приватные файлы. TLS-файлы копируются из ssl/nginx.crt и ssl/nginx.key;
если их нет, нужно положить сертификат для localhost в deploy/local/private/nginx.crt и nginx.key.

## Повторный запуск и остановка

```powershell
cd C:\Users\Илья\.vscode\CODE\Project_Smart_energy_local-features
docker compose -p smart-energy-workstation -f docker-compose.local.yml up -d
docker compose -p smart-energy-workstation -f docker-compose.local.yml ps
Start-Process https://localhost:8443/
docker compose -p smart-energy-workstation -f docker-compose.local.yml stop
```

Если после изменения кода нужна сборка, используйте deploy/local/start.ps1.
Миграции Django и индексы исходных таблиц автоматически не запускаются.
Учетные записи, агрегаты и уведомления общие с приложением на .42. После переключения нужен повторный вход.

## Адаптер

Для локальной очереди используется схема adapter_workstation в той же student.
adapter.local_setup создаёт только эту служебную схему и копирует совместимые профили как неактивные и непроверенные. Очередь и расписание серверного adapter_control остаются отдельными.
Новые профили нужно сохранять локально: подключения содержат другие адреса Docker, поэтому старые подписи не подходят.
Расписание локального адаптера изначально выключено; не включайте второй пересчёт одновременно с серверным без выбора ответственного обработчика.
Оба адаптера пишут в те же агрегаты; разные независимые источники нельзя складывать в одинаковые дни путём замены.

На странице «Источники и агрегации» в списке «Подключение» выберите «＋ Добавить подключение…»:
укажите уникальное имя, адрес, порт, базу, пользователя, пароль и SSL. Проверка выполняется в режиме чтения.
Для PostgreSQL на Windows используйте host.docker.internal, для удалённого PostgreSQL — доступный из Docker адрес.
Создание подключения не меняет базу назначения, метаданные дашборда и активный профиль.
Для пересчёта нового источника отдельно настройте справочник/соответствия ID в профиле; источнику нужны права SELECT.
Параметры подключения сохраняются зашифрованными в томе adapter-state.
Ключ — отдельный игнорируемый deploy/local/private/connection_key. Для переноса реестра нужны и том, и исходный ключ.
Пароли не возвращаются API, не попадают в профиль и Git. Изменение существующих подключений пока не предусмотрено:
создайте новое имя и новую версию профиля.

Уведомления используют общие отчёты и блокировку PostgreSQL против одновременного выполнения циклов.
SMTP по умолчанию не настроен локально; существующие почтовые секреты автоматически не копируются.
