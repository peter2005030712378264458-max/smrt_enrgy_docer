## Что изменено в расчётах

После обращения о пустом дашборде исправлена дополнительная ошибка отображения.
При выборе всех счётчиков строгая сумма становилась NULL, если хотя бы у одного
не было мощности. Первоначальная проверка HTTP 200 и наличия временных точек
этого не обнаружила: она не проверяла значения линии.

Теперь полный `value` остаётся неизвестным, а API отдельно возвращает
`available_value`, `available_meters` и `total_meters`. График и карточки
показывают доступную мощность с предупреждением о полноте, например «47 из 49».
Подсказка графика показывает число учтённых счётчиков в каждой точке.
Состав участников определяется по агрегатам выбранного периода: отсутствие
часовой строки учитывается, полностью отсутствующий за весь период счётчик
без дополнительного ожидаемого перечня обнаружить нельзя.

После обновления backend/frontend через внешний `localhost:8443` проверены
**25 и 30 октября: 24 из 24 часовых точек имеют доступную мощность, 47 из 49
счётчиков**. Реальный ответ API проверен функциями фронтенда: все 24 значения
попадают в линию и помечаются как неполные. Полная энергия этих суток остаётся
неизвестной из-за отсутствующих исходных измерений; интерфейс объясняет причину.
Успешный пересчёт подтверждает расчёт по имеющимся данным, а не наличие всех
измерений: отдельные показатели могут оставаться NULL.

При этой дополнительной правке заменены только backend и frontend. БД,
адаптер, аналитика, туннель источника и CMDBuild сохранили прежние ID контейнеров.
Предыдущие два образа и код сохранены в подкаталоге `partial-power-*` основной
резервной копии. Повторный пересчёт истории не выполнялся.

- Необязательные отсутствующие измерения сохраняются как NULL. Время и ID
  остаются обязательными; при их отсутствии или некорректности запись блокируется
  до замены существующих агрегатов. Дата и идентификатор не подставляются.
- Добавлены счётчики корректных значений каждой агрегируемой метрики.
  Средние взвешиваются по ним. Недельная мощность усредняется по времени
  отдельно для каждого счётчика, затем складывается между счётчиками.
- Энергия с неизвестными участниками не превращается в ноль или частичный итог.
  Django и аналитика используют `ENERGY_USE_STORED_ENERGY=1`.
  Старые строки без подтверждённых счётчиков не считаются проверенными;
  дашборд показывает предупреждение, недостоверные итоги остаются неизвестными.
- Нормализация метрик выполняется один раз на строку. JIT выключен только
  в читающей сессии адаптера, глобальные настройки PostgreSQL не менялись.
- Новая версия профиля прошла preview и активирована. Ежедневное расписание
  включено; `processed_until=2026-10-31`, то есть обработаны завершённые дни
  по **30 октября включительно**. Текущие сутки не агрегируются.

Подробные сценарии и ограничения: [ревью адаптера](../../adapter/REVIEW.md).
