# Интерфейс: состояние датчиков

Статус: согласованное размещение и реализуемое представление в составе SDD.
Основание: пользователь выбрал блок на главном дашборде для всех вошедших,
попросил отдельный селектор и делегировал оформление.
Термины, расчёты и открытые вопросы: [spec.md](spec.md).

## Размещение и управление

Карточка на всю ширину главного дашборда под строкой KPI, перед графиками.
Верхняя строка: «Состояние датчиков», подпись «Данные за завершённые дни»
и переключатель периода в виде группы трёх кнопок «День / Неделя / Месяц».
Выбранная кнопка выделена заливкой в существующем акцентном цвете темы.

Под заголовком — точный диапазон дат по Москве, время последней проверки и
доступность самой проверки: сколько устройств удалось проверить из справочника.
Пока нет результата, количество неисправных/молчащих не подставляется как 0.

Следующая строка — три компактных показателя: «Нет данных», «Мало данных»,
«Не удалось проверить». Числа относятся ко всему выбранному периоду и составу.
Эти названия описывают данные, а не физическую исправность оборудования.

Ниже отдельная панель поиска проблем:

| Управление | Варианты |
| --- | --- |
| Режим списка, кнопки с выделенным выбором | Все проблемы / Нет данных / Мало данных |
| Поиск | Имя или ID устройства |
| Тип | Все типы / Электросчётчики / Климатические / Метеостанция |

Начальное состояние: день, все проблемы, все типы, пустой поиск, первая страница.
Фильтры потребления в верхней панели не меняют этот блок. Переключатели блока
не меняют потребление, выбранный счётчик, дату и графики. Так климатический
датчик не исчезнет из отчёта из-за верхнего фильтра электрических счётчиков.

## Строка устройства

Компактная таблица для desktop:

| Устройство | Расположение | Состояние | Данные за период | Последнее пригодное в периоде |
| --- | --- | --- | --- | --- |
| Имя, ниже модель/тип и ID | Помещение из справочника, иначе «Не указано» | Текстовая метка, ниже причина | Пригодных измерений; процент от эталона, если известен | Московская дата/время либо «Нет за период» |

Статусы сопровождаются цветом и текстом: «Нет данных» — красный акцент,
«Мало данных» — янтарный. Ошибка проверки — нейтральная метка и объяснение,
отдельное сообщение над списком с возможностью раскрыть непроверенные устройства.
Длинные имена переносятся; полное имя и объяснение доступны без hover.
Служебные названия таблиц, подключения, DSN и внутренние ошибки не выводятся.

Сначала устройства без пригодных данных, затем с малой полнотой от меньшей
к большей; одинаковые показатели упорядочены по имени/ID. При неизвестной
полноте нет фиктивного процента. Согласованный порог — менее 90% эталона;
дополнительного статуса «критически мало» нет.

Внизу — найденное по фильтрам количество и страницы по 10 устройств.
Поиск и тип применяются ко всей выборке, а не к десяти видимым строкам.

## Состояния и адаптация

- Загрузка: плейсхолдеры строк и надпись «Проверяем данные».
- Проверка завершена, проблем нет: «За выбранный период проблем с данными
  не обнаружено». Только когда все необходимые источники проверены.
- Поиск ничего не нашёл: «По выбранным фильтрам устройства не найдены»
  и действие сброса поиска/режима списка; это не заключение об отсутствии проблем.
- Источник недоступен: объяснение неполноты проверки и список затронутых типов;
  повторная попытка не запускает пересчёт энергетических агрегатов.
- Если используется кеш, явно показывать время проверки; механизм обновления
  будет выбран после согласования источника/актуальности и замера нагрузки.
- Mobile: кнопки занимают доступную ширину, поиск и тип идут друг под другом,
  табличные строки превращаются в карточки с подписанными полями.
- Светлая/тёмная темы используют существующие токены dashboard.css;
  статус понятен без цвета, элементы доступны с клавиатуры и имеют видимый focus.

Результат проверки может относиться к прошлым дням: формулировка «сейчас не
работает» не используется. Последнее показание за пределами выбранного периода
не разыскивается молча полным сканированием истории.
