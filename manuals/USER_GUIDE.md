# Руководство пользователя Smart Energy

Smart Energy показывает энергопотребление по счётчикам и помещениям,
позволяет сравнивать периоды и находить устройства с недостатком измерений.
Для повседневной работы достаточно браузера и учётной записи приложения.

Это руководство описывает пользовательский интерфейс текущих исходников.
Установка и доступ к сайту: [инструкция](INSTALLATION.md).
Настройка источников и пересчёт: [руководство администратора](ADMIN_GUIDE.md).

## 1. Как открыть приложение

Используйте адрес, выданный администратором:

| Вариант | Типичный адрес |
| --- | --- |
| Прямой доступ к ВМ42 из внутренней сети | `https://193.232.208.42:8443/` |
| SSH-доступ к ВМ42 на данном ПК | `https://localhost:8444/` |
| Локальная workstation-версия | `https://localhost:8443/` |

Для адреса `localhost` должен работать соответствующий локальный контейнер
или SSH-туннель. Он не обозначает удалённую ВМ сам по себе.

При предупреждении о сертификате проверьте адрес и получите у администратора
публичный сертификат/инструкцию по доверию. Не вводите реквизиты на неизвестном сайте.

### 1.1. Вход и регистрация

1. На странице входа укажите электронную почту и пароль **приложения**.
2. При необходимости выберите «Запомнить меня» на личном компьютере.
3. Нажмите **«Войти»**.

Для самостоятельной регистрации нажмите **«Зарегистрироваться»**, заполните
имя, фамилию, email, пароль и его подтверждение, отметьте согласие и отправьте форму.
Новая учётная запись не получает права управления источниками.

В текущем интерфейсе кнопка «Забыли пароль?» не запускает рабочую процедуру
восстановления. При утрате пароля обратитесь к администратору.
SSH-пароль и пароль базы данных для входа в приложение не подходят.

### 1.2. Выход и тема

В меню слева нажмите карточку пользователя с подписью **«Выйти»**.
Для смены оформления используйте переключатель светлой/тёмной темы.
На общем компьютере завершайте сеанс после работы.

## 2. Разделы приложения

| Раздел | Что можно сделать |
| --- | --- |
| **Дашборд** (`/dashboard`) | Посмотреть мощность, энергию, нагрузку помещений и состояние датчиков |
| **Связи** (`/connections`) | Посмотреть помещения и автоматы, связанные с выбранным счётчиком |
| **Аналитика** (`/analytics`) | Сравнить два непересекающихся периода статистическим тестом |
| **Уведомления** (`/notifications`) | Настроить личную кривую сравнения, смотреть отчёты и состояние писем |
| **Источники и агрегации** (`/aggregation`) | Раздел оператора со статусом персонала; обычному пользователю недоступен |

Доступ к Django Admin — отдельный административный вход. Он не требуется
для просмотра дашборда, аналитики, отчёта датчиков и личных уведомлений.

## 3. Работа с дашбордом

### 3.1. Выбор данных

В верхней части страницы доступны фильтры:

- **«Счетчик»** — один прибор либо все счётчики.
- **«Помещение»** — выбор по связанному помещению.
- **«Расширенное название помещения»** — дополнительная группировка из справочника.
- **«Период»** и **дата** — календарный диапазон отображения.

При выборе одного счётчика фильтры помещений отключаются и сбрасываются.
Чтобы вернуться к выборке помещений, сначала выберите «Все счетчики».
Названия и связи берутся из базы; пользователь не редактирует их на этой странице.

| Период | Что показывает график мощности |
| --- | --- |
| **24 часа** | Выбранный московский календарный день, почасовые значения |
| **7 дней** | Выбранный день и шесть предыдущих; семь суточных позиций |
| **Весь период** | Доступную историю с недельным укрупнением |

Например, при дате **04.11.2026** и режиме **«7 дней»** диапазон —
**29.10–04.11 включительно**. Если данные есть только за два дня,
на семи календарных позициях будут два значения и пять пропусков.
Линия через неизвестные дни не проводится; отдельная известная точка видна.

Время графиков и календарные границы в приложении привязаны к Москве.
Выбранный день дашборда не меняет период отдельного отчёта состояния датчиков.

### 3.2. Показатели и единицы

| Показатель | Как понимать |
| --- | --- |
| Мощность, кВт | Уровень нагрузки; точки основного графика — агрегированные средние |
| Энергия, кВт·ч | Потребление за время; это другая величина, чем мощность |
| Максимальная мощность | Максимальное значение отображаемой агрегированной линии за период |
| Счётчики в выборке | Состав выбранного диапазона, а не число исправных физических устройств |
| Коэффициент загрузки | Отношение средней мощности к максимуму периода |
| Напряжение, В; частота, Гц | Дополнительные измерения, если они есть в источнике |

Наведите указатель на точку графика для времени, значения и числа учтённых
счётчиков. Суточные и недельные средние учитывают количество корректных
измерений, а не просто усредняют все строки одинаково.

### 3.3. Полные и доступные данные

Сообщение вида **«Учтено счётчиков: 47 из 49»** означает, что мощность
получена по доступным значениям части выбранных счётчиков. Число учтённых
может меняться от точки к точке — проверяйте подсказку графика.

Это сообщение не означает, что два устройства отсутствуют в справочнике
или обязательно были выключены весь день. Они могли не прислать мощность,
прислать NULL, либо не иметь рассчитанных значений в данном интервале.

| Отображение | Значение |
| --- | --- |
| Число `0` | Получено корректное нулевое измерение |
| `—`, разрыв графика | Значение неизвестно или отсутствует |
| **Энергия по доступным измерениям** | Известные вклады энергии без достраивания пропусков |
| Предупреждение о неизвестном полном потреблении | Для полной энергии всех участников недостаточно данных |

Например, если из 24 часов известны только 10, доступная энергия отражает
только измеренные участки. Это не оценка полных суток и не основание считать
оставшиеся 14 часов нулевыми.

Один счётчик с пропусками не блокирует формирование витрины для остальных.
Витрина может содержать строку счётчика с NULL, а график использовать только
известные значения. Успешный пересчёт не гарантирует полных данных у всех приборов.

Состав энергетической выборки определяется сохранёнными агрегатами и фильтрами.
На старых и недавно пересчитанных днях он может различаться. По текущему
writer-профилю создаются строки для всех имён его справочника, поэтому число
позиций может быть больше числа приборов, фактически приславших мощность.

### 3.4. Остальные блоки дашборда

- **«Топ счетчиков»** — ранжирование по известной полной энергии выбранного
  периода. При недостатке энергии прибор может не войти в список.
- **«Потребление по дням недели»** — таблица энергии по счётчикам и дням недели
  с цветовой шкалой. Переключайте страницы счётчиков кнопками «Назад»/«Далее».
  Знак `—` не равен нулю.
- **«Потребление по помещениям»** — данные по связям справочника помещений.
- **«Краткая сводка»** — средняя/минимальная/максимальная мощность,
  коэффициент загрузки, дополнительные показатели и фактический диапазон.

Пустой энергетический рейтинг при непустом графике мощности возможен:
для мощности доступны отдельные измерения, а полная энергия неизвестна.

## 4. Отчёт «Состояние датчиков»

Это отдельный блок на главном дашборде для всех вошедших пользователей.
Он проверяет **исходные измерения**, а не наличие строк в энергетических витринах.
Включает весь каталог: электросчётчики, климатические датчики и метеостанцию,
в том числе устройства, которые ничего не присылали.

### 4.1. Периоды и фильтры

1. Выберите **день**, **неделю** или **месяц**.
2. Дождитесь проверки исходных данных и предшествующей истории.
3. Выберите нужное состояние и тип устройства.
4. Для конкретного прибора введите имя или ID в поиск.
5. Просматривайте список по страницам; на странице до 10 строк.

Периоды означают последние завершённые **1 / 7 / 30 суток по Москве**.
Текущие незавершённые сутки исключаются. Например, 12 ноября:

| Период | Проверяемые дни |
| --- | --- |
| День | 11 ноября |
| Неделя | 5–11 ноября включительно |
| Месяц | 13 октября — 11 ноября включительно, то есть 30 дней |

Это не текущая календарная неделя или месяц. Верхние фильтры потребления
и дата основного графика не сужают данный отчёт.

### 4.2. Состояния устройств

| Состояние | Что установлено |
| --- | --- |
| **Нет данных** | За проверяемый период нет ни одного пригодного измерения; записи могли отсутствовать либо содержать только NULL/0/некорректные значения |
| **Мало данных** | Пригодные измерения есть, но их количество строго меньше 90% исторического эталона |
| **Достаточно данных** | Количество пригодных измерений не меньше 90% определённого эталона |
| **Не удалось оценить** | Источник недоступен, тип не поддержан либо истории недостаточно для эталона |

Ровно 90% проходит порог. Неизвестная оценка не означает доказанную
неисправность и не должна считаться нормальной работой.

**Особое правило этого отчёта:** NULL, бесконечности, NaN и числовые нули
не считаются пригодными измерениями. Поэтому устройство с одними нулями
попадёт в «Нет данных». Это договорённость для поиска проблемных устройств,
а не физическое доказательство поломки: нулевая температура или нагрузка
в реальности могут быть нормальными.

В остальных частях приложения корректный ноль сохраняется как ноль.

У электросчётчика проверяется общая мощность; если её нет — полная сумма
трёх корректных фаз **одной записи**. Для климатического датчика и метеостанции
достаточно одного пригодного измерения окружающей среды, например температуры,
влажности или CO₂. Одних служебных/батарейных полей недостаточно.
Повторные пакеты одного устройства с одним временем учитываются как одна метка.

### 4.3. Что такое эталон

Приложение берёт **30 завершённых дней перед проверяемым периодом**.
Для каждого устройства рассчитывает обычное суточное количество пригодных
временных меток — медиану с учётом дней без данных.

Устройство считается стабильным кандидатом, если минимум в 21 дне
положительное количество было в пределах ±20% его обычного уровня.
Для сравнения выбираются устройства той же модели с близкой исторической
частотой передачи, в пределах 20% по интервалу.

Если стабильных подходящих устройств хотя бы три, эталон — медиана их
суточных уровней. Иначе используется собственная стабильная история
прибора. Если нет и её, положительные измерения показываются с неизвестной
оценкой. Суточный эталон умножается на 1, 7 или 30 дней выбранного периода.

Это сравнение **числа измерений**, а не процента времени работы.
Например, 80% эталона не доказывает, что устройство работало ровно 80% суток.

### 4.4. Таблица и обновление

В строке указаны устройство и ID, помещение, состояние, количество данных
и последняя пригодная метка **внутри выбранного периода**. Причины неизвестных
оценок можно раскрыть в отдельном блоке.

Первый запрос может читать историю несколько минут. Не нажимайте обновление
многократно: чтение выполняется в фоне. Готовый результат и суточные статистики
кешируются до 10 минут; смотрите время проверки и отметку использования кеша.
Кнопка **«Обновить проверку»** запускает повторное чтение с ограничением частоты.

При сбое источника часть устройств получает «Не удалось оценить».
После восстановления повторите проверку. Отчёт не изменяет агрегаты,
не исправляет источник и не запускает пересчёт потребления.

## 5. Раздел «Связи»

Выберите один счётчик. Страница покажет:

- связанные помещения и расширенные названия;
- этаж/здание, если они указаны;
- автоматы и их связи с помещениями.

Пустой список означает отсутствие подходящей связи в справочнике либо
ошибку загрузки, если она показана. Это не свидетельствует об отсутствии
измерений. Для исправления привязок передайте имя/ID администратору.

## 6. Статистическое сравнение в «Аналитике»

1. Выберите счётчик или группу через доступные фильтры.
2. Укажите начало и конец первого периода.
3. Укажите второй период, **не пересекающийся** с первым.
4. Выберите альтернативную гипотезу:
   - **«Средние не равны»** — проверить отличие в любом направлении;
   - **«Первый период больше второго»** — проверить рост первого относительно второго;
   - **«Первый период меньше второго»** — проверить снижение первого относительно второго.
5. Выберите уровень значимости: 0.10, 0.05 или 0.01. Если специальных
   требований нет, исходное значение интерфейса — 0.05.
6. Нажмите **«Сравнить»**.

Конечные календарные даты выбранных периодов включаются в анализ.
Результат содержит среднюю мощность, энергию при её наличии, число наблюдений,
стандартное отклонение, z-статистику, критическое значение и текстовый вывод.

**«Отвергаем H0»** означает, что выбранный статистический критерий обнаружил
значимое различие в заданном направлении. **«Не отвергаем H0»** означает,
что оснований недостаточно; равенство и отсутствие изменения этим не доказаны.

Анализ использует доступные часовые агрегаты. Проверяйте количество наблюдений,
фактические границы и состав выборки. Ошибка недостатка данных требует
другого периода или проверки витрин. Сравнение не запускает запись агрегатов.

## 7. Личные уведомления

Раздел сравнивает почасовую фактическую энергию с ожидаемой кривой прошлых дней.
Настройки и отчёты индивидуальны. Получатель писем — email вашей учётной записи.

### 7.1. Предварительный просмотр

В блоке **«Данные и база сравнения»** задайте:

| Поле | Что выбрать |
| --- | --- |
| Режим проверки | «После завершения суток» или «В течение дня — завершённые часы» |
| Анализируемый день | Завершённая дата; в оперативном режиме используется текущий день Москвы |
| Функция сравнения | Среднее, медиана или линейный тренд |
| Период для функции | Последние N сопоставимых дней либо заданный диапазон |
| N — число дней | От 1 до 60; это объём истории, а не процент тревоги |
| Сопоставимость дней | Рабочие/выходные отдельно, тот же день недели или все дни |
| Минимум дней на каждый час | Сколько подходящих значений нужно для расчёта данного часа |
| Порог отклонения, % | Чувствительность к росту и снижению |
| Минимальное отклонение, кВт·ч | Нижняя граница абсолютной разницы |

Нажмите **«Рассчитать и показать»**. Действие строит график и таблицы,
но **не сохраняет правило и не отправляет письма**.

Под графиком раскрываются почасовые отклонения и фактические дни, использованные
для кривой. Если после изменения полей показано, что результат устарел,
повторите расчёт.

### 7.2. Правила сравнения

- Каждый час сравнивается с тем же часом выбранных предыдущих дней.
- Анализируемый день и будущее не используются для построения ожидания.
- В заданном диапазоне обе даты включительны, но берутся только дни раньше анализируемого.
- Рабочие дни — пн–пт, выходные — сб–вс; отдельного календаря праздников нет.
- Для линейного тренда нужно минимум два подходящих значения на час.
- В оперативном режиме незавершённый текущий час исключён; чтение сырья
  не перезаписывает витрины. Данные могут запаздывать до пяти минут из-за кеша.
- Пропуски полной энергии остаются неизвестными. Доступная частичная
  энергия дашборда не подставляется в сравнение.

Отклонение критическое, если ненулевая абсолютная разница не меньше
большего из двух порогов: процентной доли ожидаемого и минимального отклонения.

Пример: ожидалось 10 кВт·ч, порог 20%, абсолютный минимум 1 кВт·ч.
Порог разницы — 2 кВт·ч; факт 12 или 8 достигает его в обоих направлениях.
Если ожидание равно нулю, процент может быть не определён, но остаётся
проверка абсолютной разницы.

### 7.3. Включение фоновой проверки

1. Проверьте график и адрес получателя.
2. Отметьте **«Включить фоновую проверку и письма»**.
3. Нажмите **«Сохранить правило»**.
4. Убедитесь, что сохранённое состояние изменилось на «Включено».

Теперь проверка работает на сервере, браузер можно закрыть.
Чтобы остановить её, снимите флажок и снова сохраните правило.
Сохранённые отчёты останутся в истории.

Если указано **«SMTP не настроен»**, отчёты доступны в приложении,
а письма требуют настройки отправителя администратором. Самостоятельно
менять SMTP пользователю не требуется.

### 7.4. «Мои отчёты» и письма

В таблице показаны дата, режим/функция, факт, ожидание, результат и состояние
письма. В **«Подробнее»** доступны пояснение, порог и даты истории.
Старые записи могут называться «Прежнее суточное правило» — это результаты
предыдущего алгоритма, а не текущая почасовая кривая.

Отчёты сохраняют версию настроек. После её изменения могут существовать
разные отчёты за один день. Для одной версии оперативное письмо отправляется
не чаще одного раза за день; обновление графика не означает новую рассылку.

| Состояние | Что делать |
| --- | --- |
| В пределах порога | Дополнительных действий не требуется |
| Критическое отклонение | Проверить часы, состав данных и фактическую ситуацию |
| Недостаточно данных | Прочитать пояснение; проверить историю и полную энергию |
| Передано почтовому серверу | SMTP принял письмо; это не гарантия попадания во входящие |
| Доставка неизвестна | Не запускать повтор вслепую: возможен дубликат; обратиться к администратору |

## 8. Ответы на частые вопросы

**В сырье есть данные, но на дашборде пусто.** Основные графики читают
часовые/суточные витрины. Администратор должен проверить их пересчёт,
диапазон и ошибки заданий. Отчёт датчиков читает сырьё независимо.

**На недельном графике только два значения.** В нём семь календарных позиций,
но только две могут иметь известную мощность. Нужны агрегаты остальных дат;
переключение периода само их не создаёт.

**Число устройств стало больше.** Каталог и состав сохранённых агрегатов
могут включать молчащие приборы. Число в выборке не равно числу приславших
мощность. Например, 181 запись каталога и 49 наблюдавшихся электросчётчиков
могут одновременно быть корректными числами для разных показателей.

**«Нет данных» — значит прибор точно неисправен?** Нет. В отчёте это отсутствие
пригодных ненулевых измерений по согласованным правилам. Причиной могут быть
устройство, связь, источник или реальные нули; вывод требует проверки.

**Доступная энергия есть, а уведомления не считаются.** Уведомления требуют
полной сопоставимой энергии. Частичная сумма дашборда её не заменяет.

**После обновления прежний экран.** Выполните `Ctrl+F5`. Если не помогло,
передайте администратору адрес сайта: возможно, открыт локальный вариант
вместо обновлённой ВМ.

## 9. Что сообщить администратору при проблеме

Передайте адрес сайта, название раздела, дату и период, выбранные фильтры,
имя/ID устройства, текст ошибки и время её появления по Москве. Для проблемы
пересчёта полезен ID задания, если он вам доступен.
Не отправляйте пароли, cookie, токены и приватные ключи.
